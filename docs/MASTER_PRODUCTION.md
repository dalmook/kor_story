# 공통 제작 명령 — Hermes → Codex CLI → Flow → 편집

## 0. 작업의 정의

사용자가 선택한 이야기 한 편을 `stories/*.md`의 7컷 그대로 제작한다. 이 문서는 향후 실행 명령이다. 현재 저장소에 실제 영상이나 렌더러가 구현되어 있다고 가정하지 않는다.

목표: 9:16, 28.000초, 최종 1080×1920, 30fps, 840프레임, H.264/yuv420p, AAC 48kHz. 720p 생성 원본을 1080×1920으로 리사이즈해 내보내는 것이며, 네이티브 1080p 생성 또는 AI 업스케일이라고 부르지 않는다.

## 1. 안전하게 작업본 준비

기존 로컬 clone을 찾아 `git status`와 현재 브랜치를 확인한다. 변경이 있으면 덮어쓰거나 reset하지 않는다. 없으면 사용 가능한 정상 GitHub 인증으로 clone한다. 로컬 폴더 위치는 실제 환경에서 확인하고 새 시스템 경로를 추측하지 않는다.

AGENTS.md와 선택 문서를 읽고 기존 FFmpeg, Remotion, 이미지 생성, 무료/구독 포함 한국어 TTS, Flow 연동, Codex CLI 및 영상 스킬을 확인한다. 새 무거운 AI 영상 모델·업스케일 모델을 설치하지 않는다. 기존 렌더러를 재사용하고 부족한 최소 편집 코드만 이 저장소의 별도 작업 폴더에 만든다.

## 2. 비용 잠금 — 이미지 생성 전에도 확인

예산의 의미는 **한 편에 쓸 수 있는 Flow 크레딧 최대 50**이다. 이미지 생성과 음성도 같은 잔액을 차감한다면 그 지출 역시 원장에 포함한다. 49크레딧 영상 예산은 이미지 7장이 이미 준비되거나 별도 추가 결제 없이 확보되는 조건이다. 이미지 생성이 크레딧을 쓰면 그대로 제출하지 말고 남은 예산으로 7영상이 가능한지 다시 계산한다.

2026-09-17 공식 안내의 기준값: Gemini Omni Flash 720p 4초 x1 = 7크레딧. 실제 UI에는 버전명이 다르게 표시될 수 있으므로 모델 이름을 하드코딩해 클릭하지 말고 전체 설정과 예상 차감액을 확인한다.

매 제출 전 기록할 값:
- story_id, shot_id, attempt_id, UI 모델명, 세로 비율, 해상도, 길이, outputs=1
- 표시 예상 비용, 현재 계정 잔액, 지금까지 실제 차감, 미확정 제출의 예약 비용
- 아직 미생성인 컷 수 × 현재 단가, 제출 시각, 작업 ID, 완료/실패/차감확정/환불확정 상태

이미 차감+미확정 예약+이번 제출+남은 필수 컷 예약이 50을 넘으면 제출 금지. UI 비용이 7이 아니거나 잔액이 49 미만이면 자동으로 360p나 다른 모델로 바꾸지 않는다. 상태와 가능한 준비 결과만 보고한다.

7회 최초 생성이면 49이고 1만 남으므로 품질 재시도는 하지 않는다. 브라우저 타임아웃을 실패로 단정해 재제출하지 말고 기록/작업 ID를 확인한다. 환불은 계정에 실제 반영된 경우만 인정한다. 영상 Edit, Extend, Upscale, 출력 2개, 추가 구독, 결제를 실행하지 않는다. 웹 Flow와 과금되는 API를 같은 것으로 취급하지 않는다.

## 3. 음성과 이미지 먼저 확정

선택 문서의 한국어 대본을 이어 붙여 하나의 narration.txt를 만든다. 기존 자연스러운 한국어 TTS를 사용하여 한 화자, 한 연속 음성으로 읽힌다. 설명 문구나 장면번호는 읽지 않는다. 영화 예고편처럼 과도하게 힘주거나 로봇식 단어 끊기, 컷마다 다른 억양을 넣지 않는다.

읽기 목표는 약 24~26초이며 시작 0.15~0.35초, 끝 여운 0.8~1.5초를 두되 **실제 생성된 음성 길이를 측정**한다. 글자 수로 28초라고 확정하지 않는다. 너무 길면 대본 의미를 보존해 짧게 다듬고 연속 음성을 다시 만든다. 1.08배를 넘는 속도 보정으로 억지로 끼워 넣지 않는다. 화자의 변경이나 큰 서사 변경은 하지 않는다.

핵심 문장을 실제로 듣고 오독·호흡·음색·말끝이 자연스러운지 확인한다. 청취 기능이 없다면 파일을 제공하고 청취 미검증 상태를 남긴다. 기술적 길이 검증으로 음성이 자연스럽다고 주장하지 않는다.

이미지 프롬프트는 다음 순서로 조합한다:
`공통 화풍 블록 + 해당 이야기 캐릭터 블록 + 해당 컷 이미지 프롬프트 + 공통 제외사항`.

처음 확보한 인물 이미지를 참조 자산으로 고정한다. 새 얼굴을 컷마다 독립 생성하지 않는다. 이미지 단계에서 7장의 의상·얼굴·소품·화풍·시선·화면 방향을 대조한다. 주인공의 얼굴/손이 잘못된 이미지는 Flow에 넣지 않는다. 어린이는 성인으로 바뀌지 않아야 한다.

## 4. Flow 7컷 생성

컷별 시작 이미지 한 장만 넣고 해당 모션 프롬프트를 제출한다. 모두 별개의 4초 생성이다. 서로 다른 이미지로 시작/끝 프레임을 연결해 자동 장면 전환을 시키지 않는다. 한 컷에 한 핵심 동작, 보조 환경 움직임은 낮게 유지한다.

프롬프트의 0~1초 같은 시간은 연출 의도이지 정확한 타임코드 보장이 아니다. 실제 클립의 사건 위치를 확인하고 필요하면 후반 효과/음향 시점을 움직인다. 카메라 이동은 4초에 화면 폭 약 2~5% 범위의 절제된 이동을 목표로 하며 과한 360도 회전과 복잡한 추격은 금지한다.

다운로드 파일은 이미지 파일과 같은 컷 번호를 유지한다. 원본 오디오는 편집에서 기본 음소거한다. 표정/손/의상이 무너지거나 중심 동작이 없는 클립을 성공으로 표시하지 않는다. 비용 재시도 대신 작은 오류는 로컬 마스크·안개·크롭으로 숨길 수 있는지 평가하되 중요한 서사 동작을 삭제하지 않는다. 회복 불가능하면 해당 컷 FAIL로 남기고 아직 생성 가능한 다른 컷과 편집 자산을 마무리한다.

Flow 연동을 실제로 찾지 못하면 `flow_prompts/01.txt`~`07.txt`, 시작 이미지, `flow_generation_checklist.md`를 먼저 완성한다. 로그인 우회나 가짜 API를 만들지 않는다. 사용자가 직접 생성해서 `flow/01.mp4`~`07.mp4`를 넣으면 다음 단계부터 재개 가능하게 한다.

## 5. Codex CLI에 전달할 하위 명령

```text
선택한 이야기 문서와 docs/INK_EDITING_SPEC.md를 읽어.
기존 FFmpeg/Remotion 환경을 조사하고 재사용해. 아직 자산이 없으면
검증 가능한 편집 프로젝트와 자산 누락 검사를 먼저 구현해.

7클립 각각 120프레임, 시작 프레임 0/120/240/360/480/600/720,
합계 840프레임으로 타임라인을 만들어.
원본 FPS는 실제 메타데이터로 확인하고 CFR 30으로 정상화해.
6개 컷 경계에 문서의 수묵 오버레이를 합성해. 전환 때문에
총 프레임을 빼는 TransitionSeries.Transition/xfade 구조는 사용하지 마.
설치 버전의 기능을 확인하고 일반 Sequence + AbsoluteFill 또는
동일 기능의 로컬 합성으로 구현해. 스타일 효과는 매 프레임 결정론적이어야 해.

narration.wav를 한 트랙으로 사용하고, 자막 시점은 실제 음성에서 맞춰.
TTS 텍스트와 실제 음성의 정합성, 영상 7개 존재, 오디오 샘플레이트,
누락 파일, 840프레임, 검은 화면, 고정 프레임, 볼륨 클리핑,
한글 오탈자·잘림·가독성·내레이션 싱크를 검사해.
AI가 만든 형태 이상과 음성 자연스러움은 실제 시청·청취로 별도 검수해.

run 폴더 안에 편집용 edit_plan.json, 프로젝트 소스, 자막 SRT,
내레이션, 최종본, 클린본, qa.json, QA.md, 편집 재실행 명령을 남겨.
미디어를 공개 Git에 올리지 마. 누락 자산을 정지 이미지로
몰래 채운 뒤 완료 처리하지 말고 NEEDS_FLOW_INPUT 또는 FAIL로 반환해.
```

## 6. 저장 구조와 재개

```text
runs/<story_id>/<run_id>/
  STATUS.md
  narration.txt
  character_sheet.md
  image_prompts/01.txt ... 07.txt
  images/01.png ... 07.png
  flow_prompts/01.txt ... 07.txt
  flow/01.mp4 ... 07.mp4
  flow_generation_checklist.md
  credits.jsonl
  edit_plan.json
  audio/narration.wav
  captions/narration.srt
  project/                  # 실제 사용한 편집 코드
  exports/<story_id>_28s.mp4
  exports/<story_id>_clean.mp4
  evidence/contact_sheet.jpg
  evidence/metadata.json
  evidence/qa.json
  QA.md
```

run_id는 현재 시각 등 충돌 없는 값을 실제 환경에서 만든다. 기존 run을 덮어쓰지 않는다. 재개할 때 완료된 Flow 컷은 재생성하지 않는다. 부재 상태를 자동으로 무료 재시도 가능 상태로 취급하지 않는다.

edit_plan.json에는 story_id, fps=30, duration_frames=840, 7개 shots(id/start_frame/duration_frames=120/source_file/image_file/narration/subject_action), 6개 transitions(boundary_frame/type/window_frames/anchor/direction), narration_file, captions_file, budget_cap=50, expected_initial_credits=49, actual_spent, source_resolutions, qa_status를 기록한다. credits 실제 값은 실행 전 null 또는 미확인으로 두고 예상값을 실지출로 복사하지 않는다.

## 7. 완료 판정

문서/준비 완료와 영상 완료를 구분한다. 영상 PASS의 필수 조건은 7개 실제 Flow 원본, 실제 재생 가능한 840프레임 영상, 연속 음성, 6개 전환, 실제 음성에 맞는 자막, 비용 원장, 기술 검수와 시청/청취 여부 공개다. 자동 검수만 통과한 경우 HUMAN_REVIEW_REQUIRED로 표시한다.

최종 보고에는 선택 이야기, 파일 위치, 실제 모델/해상도, 실제 비용/남은 잔액, 생성 실패 여부, 로컬 보정 내역, 음성/영상 검수 방법, 차단 요인을 적는다. YouTube 등 업로드·예약 발행은 별도 요청 없이 하지 않는다.
