# Codex 직접 제작 절차 — 끝까지 실행하되, 과금과 품질은 단계별 확인

`START_CODEX.md`를 받은 Codex는 감독이자 실행자다. Hermes에게 계획을 다시 넘기지 않는다. 아래 순서로 실제 도구를 사용한다. 보조 Python의 prepare가 끝났다는 것은 제작이 끝났다는 뜻이 아니다.

## A. 작업본과 도구 확인 — 비용0

현재 저장소와 Git 상태를 확인해 사용자 수정사항을 보존한다. 선택 episode_id 하나만 작업하고 새로운 run 경로를 만든다. 이미 있는 run은 목록·상태·원장을 확인한 뒤 재개하며 덮어쓰지 않는다.

이미지: 현재 Codex 세션의 네이티브 이미지 생성/편집 도구와 설치된 스킬을 실제로 발견하고 설명을 읽는다. 이름이나 `imagegen` 명령어가 있을 것이라고 추측하지 않는다. 네이티브 기능이 있으면 그 도구로 실제 원화를 생성한다. 없다면 승인된 기존 이미지 연동을 확인한다. 추가 결제 없는 도구도 없다면 BLOCKED_TOOL_ACCESS로 정확한 이유를 남긴다. 유료 Images API를 몰래 대신 호출하지 않는다.

Flow: 현재 승인된 브라우저·컴퓨터제어·관련연동을 실제 확인한다. 공식 기능 발표는 현재 세션의 사용권이나 연결상태를 보장하지 않는다. Windows나CLI환경에서도 실제 도구 목록을 확인하고, 사용할 수 없는 macOS 전용 기능을 있다고 쓰지 않는다. 도구의 브라우저 프로필·파일 업로드 기능·다운로드 위치를 확인한다. 사용자의 세션/쿠키를 몰래 추출하거나 새로운 로그인 수단을 우회하지 않는다.

음성/음악: 기존 TTS, 실제지원 KO/EN목소리, 사용권/요금, 기존 허가음원과 편집기를 확인한다. 추가 비용이 필요한 모델은 호출 전 멈춘다. 배경음이 없으면 기존 허가음원 또는 공식 라이브러리에서 조건에 맞는 실제 곡을 찾는다. 이 단계에서 음성을 못 만들거나 음악도 준비할 수 없다면 영상49크레딧부터 쓰지 않는다.

preflight.json에 도구명·버전·상태·추가비용확인·로그인여부를 기록한다. 확인하지 못한 값은null/false, 성공을 뜻하는임의값은금지한다. 막힌 경우 질문은 “Flow 로그인 필요”처럼 필요한 조치 하나에 한정한다. 자막색/크기/효과선택은 이미 지침이 있으므로 사용자에게 다시 정하게 하지 않는다.

## B. 기존 원본 우선 점검

사용자의 실패MP4는 기준영상이지 클린원본이 아니다. 같은 작업폴더에서 Flow01~07 원본, 원화, 내레이션 stem, 렌더소스, job_id, 원장을 찾아 실제로 검사한다. 자막과못생긴전환만문제라면 원화/Flow를 다시만들기보다 깨끗한소스로재편집한다. 좋은원본을유지하는것이기본이다.

원본이정말없거나내용/모션이부적합한컷만생성후보로지정한다. 실제추가지출과과거지출은별도필드에기록하되같은episode의허용예산을run이름으로초기화하지않는다. 원본의보호표시/워터마크를제거하지않는다. 완성MP4의자막을AI로지우며“깨끗한원본을찾았다”라고하지않는다.

## C. 실행 계획과9개 이미지

`python tools/codex_production.py check` 뒤 새run에 `prepare --episode ... --out ...`을 실행한다. image_prompts9개, flow_prompts7개, audio/원고2개, 잠정자막, run_plan과자산상태가 만들어진다. 실제이미지는아직없으며이를확인한다.

먼저 캐릭터 참조와 첫 원화1장을 만든다. 아이 나이·키비율·얼굴·옷·리본, 호랑이무늬,한지/먹/명암을검수한다. 그 참조를 모든후속이미지에넘긴다. 한장의텍스트에9장collage를요구하지말고, 각각의원본이미지를확보한다. 서비스가반환한크기와출처를기록한다.

오프닝1장+본문7장+예고/엔딩1장을모두만든다. 시작화면과예고화면도코덱스가직접실제도구로생성한다. 제목과자막은생성이미지에넣지않고후반에서그린다. 눈/손/다리/옷/공간/서비스표시/안전영역을검수한다. 무료·포함분으로허용된이미지수정만정해진범위에서수행하고그것도무한반복하지않는다.

9장접촉표를만들어화풍과인물동일성을검토한다. 카드의텍스트여백과본문의자막영역까지확인한뒤승인목록을저장한다. 문제이미지를Flow로보내결함을확대하지않는다.

## D. 글자와 전환의 사전 미리보기 — Flow 제출 전에

최종해상도1080×1920에실제사용폰트를로드해 제목108/92, 자막72/68을그린다. `design/layout_reference.html`은수치의샘플이지최종배경이아니다. 실제원화로교체한화면에서검수한다.

반드시볼것: 오프닝제목, 가장긴KO자막, 가장긴EN자막, 밝은배경자막, 어두운배경자막,2줄끝부분,예고제목. glyph폭과box경계를측정하고,원본과360×640미리보기를모두확인한다. 화면미리보기scale이글자크기에중복적용되지않게한다.

임시스틸을사용해8프레임디졸브와cut을시연하는4~6초로컬프리뷰를만든다. 이것은검수용이며최종영상으로납품하지않는다. 블랙/베이지가림막,삼각형,텍스트튐이있으면수정한뒤에만Flow를진행한다. 허용없는효과를“더화려해졌다”는이유로추가하지않는다.

## E. 내레이션/음악 선확정

KO와EN을각각한화자의연속트랙으로읽힌다. 첫대상은상세JSON의짧은v4원고를쓴다. 다른편은기존원고의내용을보존하고실제말속도/읽기시간이넘치면의미변경없는간결한수정과변경기록을남긴다.

원본목소리를듣고자연스러운문장끝과쉼을확인한다. ASR/정렬도구는음성텍스트를새로창작하는도구가아니다. 전사결과를기준원고와대조하고타임스탬프를검수한다. target.json의목표시각을aligned.json에이름만바꿔넣지않는다. 실제로확인한큐만 `audio_alignment_reviewed` 또는 `manually_listened`로표시한다.

빠르다고전체atempo로속도를고치지말고TTS발화설정/원고/검증된문장사이쉼으로해결한다. 잘린음절과다른화자톤의이어붙이기금지. BGM은필수로확보하고실제곡을정상속도로들어VO와충돌하지않는지확인한다. 저작권표시가필요하면최종KO/EN설명에도추가한다.

## F. Flow 실제 조작 — 신규 생성이 필요한 컷만

1. 승인된브라우저/컴퓨터제어로사용자가접근가능한Flow프로젝트를열고현재로그인/계정을확인한다. 프로젝트명은episode_id/run_id로구별한다. 계정선택이모호하면진행하지않는다.
2. 화면을보고현재UI의이미지시작프레임생성기능을선택한다. 고정좌표클릭이나오래된버튼명을맹신하지말고접근성레이블/현재스크린샷으로확인한다.
3. 본문01.png를시작프레임에업로드한다. 끝프레임에다음컷을넣지않는다. 해당flow_prompts/01.txt만입력하고내레이션원고는넣지않는다.
4. 실제설정이9:16,720p,4초,출력1개,표시비용7인지확인하고전송전스크린샷/값을저장한다. 단가/해상도/출력개수가다르면제출금지。비용원장에확정/미확정/이번/남은필수컷예약을반영한다.
5. 생성1회를제출하고실제job_id/시각을기록한다. 완료까지상태를확인한다. UI가잠깐멈춰도다시버튼을누르지않는다. 작업이력이있는지먼저검사한다.
6. 실제다운로드링크/브라우저다운로드로원본을저장한다. 성공화면스크린샷을영상파일로대체하지않는다. 확장자만mp4인HTML이아닌지ffprobe로확인하고해시를저장한다.
7. **첫신규클립을0.5초간격또는실제재생으로검수**한다.주동작이중간에한번,마지막에안정,얼굴/손/입/옷/화풍일관성. 실패면유료재시도없이멈추고이미지/모션설정과남은예산을보고한다. 실패클립을사용자가못볼것이라고생각해숨기지않는다.
8. 첫클립이적합하면나머지필요컷을하나씩진행한다. 매요청마다설정과실제비용을확인한다. 영어판이나오프닝/예고를위한추가Flow작업은없다.7개만필요하며모두이미유효하게있으면호출0회다.

무료환불은실제계정반영이확인된것만인정한다. “실패했으니공짜일것”이라며재시도하지않는다. 제한회피·다계정분산·유료API우회는없다.

## G. 편집과 두 언어 출력

기존Remotion/FFmpeg를재사용하되설치버전의실제공식문서/스킬을확인한다.없는버전전용컴포넌트를추측하지않는다. 필요최소한의로컬코드를작성하고영상은실제파일경로로연결한다.

오프닝60프레임,본문각120프레임,예고90프레임. 타임라인을990으로고정하고DESIGN_BIBLE의중심블렌드를구현한다. 효과는프레임기반결정론적이며CSS무한animation/타이머/Math.random프레임난수를사용하지않는다. 두언어의시각적사건/카메라/전환은동일하고텍스트/음성만다르다.

공용마스터를무음·무문자로렌더한다. 각언어의타이틀/자막/파트/분류를합성하고BGM/SFX와내레이션을믹스한다. 마지막3초에다시VO를끼워넣지않는다.최종파일명은<episode_id>_ko.mp4와_en.mp4. 같은공용마스터해시를각locale manifest에기록한다.

## H. 검수와 수정 루프

`qa --run ...`은메타데이터/실측큐형식만검사한다.별도로폰트bounds·워터마크보존·검은프레임·장면붕괴·순서·lip sync·한글오탈자/영문줄바꿈·VO+BGM분리청취·효과음싱크·전체음량을검수한다.990프레임이면서33초가아니거나음성/자막이30초예고로넘어가면실패다.

작은로컬디자인문제는최대3회수정→관련구간재렌더→다시확인한다.이는Flow유료재생성승인이아니다. 360×640축소전체본과원본일부를보고읽기/그림감상이가능한지판단한다. 기준영상의y1660대작은자막이나거대덮개가다시보이면납품하지않는다.

실제목소리를들을수있는도구가없으면정렬/음량만확인했다고쓰고 LISTENING_REVIEW_PENDING을남긴다.그상태에서“음성자연스러움까지검수완료”라고하지않는다. 실제모바일이없으면360미리보기검수와실제기기검수를구분한다.

## I. 납품
