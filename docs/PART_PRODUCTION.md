# 파트 분할 제작 규격 / v3

## 1. 실행 단위와 예산

story_id는 이야기, episode_id는 실제 제작할 28초 단위다. 예를 들어 story_id=01_sun_and_moon, episode_id=01_sun_and_moon_p02다. 구미호와 매화령은 단편이므로 기존 ID를 두 필드에 같이 쓴다.

manifest의 part_number, part_count, previous_episode, next_episode는 연결 정보이지 작업 큐가 아니다. auto_advance=false를 유지하고 요청받은 파트 하나만 실행한다.

현재 구성은 3개 이야기×2파트+2개 단편=8편이다. 편당 7컷이므로 총56컷, 한국어·영어 출력은 총16개다. 실제 단가7이 확인되는 조건에서 파트당49, 2부작98, 전체392크레딧 예상이다. **50은 한 파트의 상한이지 이야기 전체의 상한이 아니다.** 이미 있는 호환 클립을 재사용하는 경우에는 실지출 원장으로 계산한다.

## 2. 나누는 지점

| 이야기 | 1부의 작은 결말과 연결 | 2부의 시작과 완결 |
|---|---|---|
| 해와 달 | 집 탈출과 나무 피신에는 성공하지만 호랑이가 발견한다 | 같은 밤 나무 위 위기에서 동아줄의 구원과 해·달까지 |
| 선녀와 나무꾼 | 날개옷을 잃은 선녀가 지상에 남고, 귀환 수단은 궤짝에 갇힌다 | 몇 해 뒤 가족의 모습에서 옷을 되찾고 귀환하는 결말까지 |
| 도깨비 | 우연한 개암 소리로 방망이를 얻는다 | 보물을 탐낸 이웃의 모방과 실패, 빈손 퇴장까지 |

1부는 한 사건의 결과를 주고 다음 질문을 남긴다. 2부는 처음 보는 사람도 인물과 위기를 이해하도록 첫 장면에 맥락을 담는다. 별도의 지난 이야기, 예고, 로고 컷을 추가하지 않는다. 기존28초를 반으로 자르거나 느리게 늘리지 않고, 각 파트에 새28초·7컷을 설계한다.

## 3. 연속성 자산

```text
series_assets/<story_id>/
  character_refs/
  prop_refs/
  palette.json
  continuity.json
  part_01_end.json
runs/<episode_id>/<run_id>/
  shared/flow/01.mp4 ... 07.mp4
  shared/picture_master.mp4
  ko/  en/  exports/
  credits.jsonl
  QA.md
```

continuity에는 실제 참조 파일과 SHA-256, 얼굴·옷·장신구·키 비율, 소품의 소유자와 상태, 건물·나무 배치, 시간·계절, 화면 방향과 바람 방향을 기록한다. 파트가 완성되면 마지막 프레임 경로와 해시도 남긴다. 실제 자산이 없을 때에는 null과 PLAN_ONLY로 표시하고 경로·해시를 지어내지 않는다.

해와 달은 나무줄기 왼쪽, 가지 오른쪽, 달 오른쪽 위, 남매의 옷과 리본, 호랑이 위치를 유지한다. 선녀와 나무꾼은 같은 얼굴·비취핀·비단색·둥근 잠금쇠·궤짝 왼쪽 아래 흠집을 유지하고, 2부 첫 컷에서 시간 경과와 아이 둘을 도입한다. 도깨비는 착한 사람의 회색 왼소매 패치와 욕심쟁이의 갈색 옷·황토깃을 구별한다. 방망이는 1부 뒤 나무꾼 소유이므로 2부의 도깨비 집에는 없어야 한다.

2부가 참조를 사용한다는 것은 1부 클립을 그대로 반복한다는 뜻이 아니다. 2부 단독 제작에 필요한 참조가 부족하면 무료 이미지 준비 단계에서 보완하고, 이전 파트 영상 전체를 자동 생성하지 않는다.

## 4. 28초 안의 여백

각 컷120프레임, 시작0/120/240/360/480/600/720, 총840프레임이다. 기존 수묵 효과 규격을 유지하고 여섯 경계에 지정된 전환을 넣는다. 겹침으로 길이를 빼지 말고 컷 경계 위 가림막으로 합성한다.

새 파트는 약20~23초의 자연스러운 실발화와 나머지5~8초의 호흡·행동·음악을 디자인 목표로 삼는다. 이는 무음이 포함된 WAV의 전체 길이가 아니라 실제 말하는 시간의 목표다. 마지막 말은27.2초 이전에 끝나고, 마지막 약0.8초 이상은 여운을 남기도록 실제 음성으로 확인한다.

4초마다 일률적으로1초씩 쉬거나 TTS를7개로 잘라 붙이지 않는다. 한 문장 뒤 짧게 쉬기도 하고, 두 문장 뒤 행동을 더 오래 보여주기도 한다. 첫 발화는 약0.2~0.4초 안에 시작하며 반전 단어는 화면 공개보다 앞서지 않는다. 빠른 낭독이 필요할 만큼 길면 같은 뜻의 문장을 줄인다.

구미호·매화령은 원고를 보존한 단편이다. 기존 분량도 실제 청취로 확인하되 이번 분할을 이유로 그 두 이야기의 결말을 임의 변경하지 않는다. 단어 수나 시간 목표만으로 음성 품질 PASS를 내리지 않는다.

## 5. 시작과 끝

파트 표시는 첫 컷 상단의 작은 후반 오버레이로 넣는다. 예: `해와 달 · 1부` / `Sun & Moon · Part 1`. 생성 이미지와 공용 마스터에는 문자를 넣지 않는다.

1부 끝에 다음 제목을 넣더라도 마지막 움직이는 컷 위에 약0.8~1.2초만 작게 표시한다. 사건이나 내레이션 자막을 가리지 않는다. 추가 CTA 낭독이나 예고 영상은 없다. 2부와 단편에는 불필요한 다음 편 표시를 넣지 않는다.

요청되지 않은56초 합본이나 자동 게시를 만들지 않는다. 추후 합본을 명시적으로 요청받으면 두 파트의 클린 마스터를 로컬에서 연결하고 내레이션·파트 라벨의 연결을 검수한다. 추가 Flow 생성은 기본 해결책이 아니다.

## 6. v2 마이그레이션

03/05의 상세 문서·TXT·ID는 그대로 둔다. 01/02/04의 최상위 stories 문서는 시리즈 안내가 되고 새 실행 문서는 episodes/*_p01.md와 *_p02.md다. 세 이야기의 이전 단일편 TXT는 활성 narration에서 제외하고 archive/v2/snapshot에 원본 그대로 보관한다. 사용자PC의 기존 run이나 완성 영상을 삭제하지 않는다.

기존 클립을 재사용할 때는 새 파트의 의미·구도·인물·소품 상태와 맞는지 확인하고 episode_id/shot_id/원본 해시/재사용 이유를 기록한다. 내용이 맞지 않는 예전 완성본에 새 음성만 붙이지 않는다. 기존7개 클립을14개 새 원본이라고 보고하지 않는다. 아카이브의 옛 지시는 실행하지 않는다.

## 7. 검수

각 파트의 원본7개, 두 언어840프레임 출력, 여섯 경계, 동일 공용 마스터 참조, 캐릭터·소품 연속성, 실지출, 스포일러 순서, 한 사건의 결말과 실제 음성 여백을 확인한다. 한 파트 완료와 전체 이야기 완료는 구분해 보고한다. 문서·원고 검사는 실제 시청·청취를 대체하지 않는다.
